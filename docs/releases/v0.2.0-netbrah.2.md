# speedread 0.2.0-netbrah.2 — no folder prompt; one plugin for every agent host

A pre-release of the [netbrah fork](https://github.com/netbrah/speedread/blob/v0.2.0-netbrah.2/docs/FORK.md) of [speedread](https://github.com/brennengreen/speedread) by Brennen Green, based on upstream `37abea2` (0.1.0 plus Luau support). It is not an upstream release.

> **Not yet run on macOS.** Both macOS binaries were cross-compiled on Linux and have never been executed on a Mac. The two Linux binaries were run before release (x86_64 natively, arm64 under QEMU). Treat the first install on a Mac as the test.

## What changed since 0.2.0-netbrah.1

- **Nothing to configure.** The Claude Desktop bundle no longer asks for a folder, and neither does any plugin. The server starts as `speedread mcp --unrestricted --no-cwd-root`: it reads the paths the agent names, by absolute path or under a `base_dir`, anywhere your account can read, and it refuses a path-less call rather than searching wherever it was launched. Its instructions tell the model so. The folder fence is gone; your host's tool-approval prompt is the remaining control. To keep the fence, register the binary yourself with `mcp --root <DIR>`.
- **One plugin, `speedread-netbrah`,** for Claude Code, Claude Cowork, Cursor, Grok Build and Perplexity Computer. It is text only: manifests, a skill and a launcher that downloads the binary for your machine from this release on first use and checks its SHA-256.
- **Four platforms:** macOS on Apple Silicon and Intel, Linux on x86_64 and arm64 (static). Not Windows; WSL counts as Linux.

The reading, searching and tracing code is unchanged from 0.2.0-netbrah.1.

## Install

Full instructions: [docs/DISTRIBUTION.md](https://github.com/netbrah/speedread/blob/v0.2.0-netbrah.2/docs/DISTRIBUTION.md).

| Host | How |
|---|---|
| Claude Code | `claude plugin marketplace add netbrah/speedread#v0.2.0-netbrah.2` then `claude plugin install speedread-netbrah@netbrah-speedread` |
| Claude Cowork | Customize > Plugins > upload `speedread-netbrah-plugin.zip` |
| Claude Desktop chat | open `speedread-aarch64-apple-darwin.mcpb` (Apple Silicon) |
| Cursor | copy `plugins/speedread-netbrah` into `~/.cursor/plugins/local/` and reload |
| Grok Build | `grok plugin install netbrah/speedread@v0.2.0-netbrah.2#plugins/speedread-netbrah --trust` |
| Perplexity Computer | Plugins > Add custom > Import plugin from GitHub > `https://github.com/netbrah/speedread/tree/v0.2.0-netbrah.2/plugins/speedread-netbrah` |

It installs as **speedread (netbrah fork)**, beside upstream's rather than over it. Both offer tools named `map`, `read`, `search` and `trace`, so enable one at a time.

The macOS binaries need macOS 11 or later; the arm64 one is ad-hoc signed, neither is notarized. If macOS refuses a file after a browser download: `xattr -d com.apple.quarantine <file>`. A download made by `curl`, which is what the launcher uses, is not normally quarantined.

## Command line

```sh
mkdir -p ~/.local/bin
curl -fsSL https://github.com/netbrah/speedread/releases/download/v0.2.0-netbrah.2/speedread-aarch64-apple-darwin.tar.gz | tar -xz -C ~/.local/bin
speedread --version   # speedread 0.2.0-netbrah.2
```

Replace `aarch64-apple-darwin` with `x86_64-apple-darwin`, `x86_64-unknown-linux-musl` or `aarch64-unknown-linux-musl`.

## What was tested

Before publication, on Linux x86_64 (2 vCPU sandbox):

- **Source.** `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` (Linux, and again for `aarch64-apple-darwin`), and all 98 tests pass, including one new test that starts the server the way every package now does and checks that it reads by absolute path, refuses a path-less call, and says so in its instructions.
- **Linux binaries.** Both are static (no interpreter, no shared libraries). The x86_64 binary run natively and the arm64 binary run under QEMU gave byte-identical answers to the tested build on 15 queries over the ripgrep source (`map`, `search`, AST search, scopes, `trace` callers/implementations/callees, `read` by path, symbol, line range and heading, JSON output). Each, started as an MCP server with the shipped arguments, refused a path-less `map` and answered a `trace` given `base_dir`. Timing on the zod source was within 5% of the tested build.
- **macOS binaries.** Inspected, not run: correct CPU type, minimum macOS 11.0, only system libraries linked, arm64 ad-hoc signed. The binary inside the `.mcpb` is byte-identical to the one in the arm64 tarball; the bundle's manifest has no `user_config` and starts `mcp --unrestricted --no-cwd-root`.
- **Launcher.** 11 checks (`scripts/test-launcher.sh`) under `sh`, `dash` and `bash` against a local mirror: download and cache, second run without the network, a checksum mismatch installs nothing, a failed download names the URL, `SPEEDREAD_BIN`, `SPEEDREAD_NO_DOWNLOAD`, the data-directory fallbacks, and a `speedread` already on `PATH` used only if its version matches. `shellcheck` clean.
- **Manifests.** `claude plugin validate` (plugin, marketplace and the unpacked zip), `grok plugin validate`, Cursor's `validate-template.mjs`, and the Agent Plugins 1.0.0 JSON schemas all pass.
- **Claude Code 2.1.197** (installed from a local checkout): marketplace add, plugin install, `claude mcp list` shows the server connected.
- **Grok Build 1.0.77** (installed from a local checkout): install with `--trust`, `grok mcp doctor` reports the server started, handshake completed, 4 tools found.

Checks against the published files (a real download through the launcher, and installs from this tag in Claude Code and Grok Build) can only run after publication; their results are added to the release page and to this file on the branch.

Not tested: anything on macOS; Claude Desktop and Claude Cowork (no way to run either here); Cursor at runtime (its command line needs a login to manage plugins, so only the manifest validator ran); Perplexity's import dialog.

## Known limits

- The macOS builds have only been compiled and inspected, as above.
- The binaries were built from this tag's parent commit; the tag adds only the checksums in the plugin launcher and documentation (`scripts/fork-release.sh` explains why).
- The plugin's first use needs network access to github.com. `SPEEDREAD_BIN`, `SPEEDREAD_NO_DOWNLOAD` and `SPEEDREAD_RELEASE_URL` are the ways around that.
- Not listed in any curated directory (Anthropic's, Cursor's, the MCP Registry). Those need the repository owner's sign-in; the steps are in docs/DISTRIBUTION.md.
- Limits carried over from 0.2.0-netbrah.1: content after a line longer than 4 MiB is not text-searched (the answer names the files); a working set larger than `--cache-mb` is re-parsed on access; a whole-tree request on a Chromium-sized tree can hit the 10 s deadline and say so (`--deadline-ms 30000` waits longer).
